# NEXORA

![Flutter](https://img.shields.io/badge/Flutter-02569B?style=for-the-badge&logo=flutter&logoColor=white) ![Dart](https://img.shields.io/badge/Dart-0175C2?style=for-the-badge&logo=dart&logoColor=white) ![Firebase](https://img.shields.io/badge/Firebase-DD2C00?style=for-the-badge&logo=firebase&logoColor=white) ![Kotlin](https://img.shields.io/badge/Kotlin-7F52FF?style=for-the-badge&logo=kotlin&logoColor=white) ![Android](https://img.shields.io/badge/Android-3DDC84?style=for-the-badge&logo=android&logoColor=white) ![Google Maps](https://img.shields.io/badge/Google_Maps-4285F4?style=for-the-badge&logo=googlemaps&logoColor=white)

> *Аниме и манга в одном месте: смотри, читай, отмечай прогресс и собирай профиль, которым хочется поделиться.*

Мобильное приложение для аниме и манги на Flutter/Dart. Современная архитектура, поддержка оффлайн-режима, синхронизация с облаком, интерактивные карты, кастомизация профиля и нативные возможности устройств.

## Цель и аудитория

**Цель.** Сделать место, где удобно смотреть аниме и читать мангу: быстро найти тайтл, понять, о чём он, продолжить с того места, где остановился, и держать весь прогресс в одной библиотеке.

**Аудитория.** Зрители и читатели аниме и манги, которым нужен один удобный каталог и личный список вместо отдельных сайтов, закладок и заметок.

## Известные ограничения

- **iOS** не настроен для карт (нет ключа в `AppDelegate`), геолокации, камеры и push (нет строк разрешений и entitlements). Остальной интерфейс работает.
- Сортировка «по названию» в каталоге работает только внутри уже загруженных страниц (API не умеет сортировать по названию на сервере).
- Оценки и отзывы хранятся только на устройстве и не синхронизируются с облаком.
- Данные OpenStreetMap в некоторых районах неполны, поэтому рядом может ничего не найтись.
- Описания тайтлов приходят от Kitsu на английском.
- Переведены на английский нижнее меню, меню и настройки; остальные экраны только на русском.

## Настройка и запуск

**Требования:** Flutter (stable), Android-устройство или эмулятор, свой проект Firebase.

Файлы с ключами в Git не хранятся (см. `.gitignore`), поэтому перед первым запуском их нужно создать.

1. Установите зависимости:
   ```bash
   flutter pub get
   ```
2. Подключите Firebase. Команда создаст `lib/firebase_options.dart` и `android/app/google-services.json` — без них проект не собирается:
   ```bash
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
3. Для карты добавьте ключ Google Maps в `android/local.properties` (без ключа приложение собирается, но карта не загружается):
   ```properties
   MAPS_API_KEY=ваш_ключ
   ```
4. Загрузите правила из `firestore.rules` в Firebase Console → Firestore Database → Rules.
5. Запустите проект:
   ```bash
   flutter run
   ```

**Подпись релиза (необязательно).** Если в `android/key.properties` указаны `storeFile`, `storePassword`, `keyAlias` и `keyPassword`, release-сборка подписывается этим ключом, иначе — отладочным.

**Секреты для CI.** Сборке APK в GitHub Actions нужны секреты `FIREBASE_OPTIONS_B64`, `GOOGLE_SERVICES_JSON_B64` и `MAPS_API_KEY` (Settings → Secrets and variables → Actions). Значения для первых двух на macOS можно скопировать так:

```bash
base64 -i lib/firebase_options.dart | pbcopy          # FIREBASE_OPTIONS_B64
base64 -i android/app/google-services.json | pbcopy   # GOOGLE_SERVICES_JSON_B64
```
