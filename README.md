# NEXORA

![Nexora](.github/images/Yvonne%28Arknights-Endfield%29.jpg)

> *Аниме и манга в одном месте: смотри, читай, отмечай прогресс и собирай профиль, которым хочется поделиться.*

Кроссплатформенное мобильное приложение для аниме и манги на Flutter/Dart. Личный учебный проект для изучения мобильной разработки, UI/UX, архитектуры приложений, REST API и локального хранения данных.

## Цель и аудитория

**Цель.** Сделать место, где удобно смотреть аниме и читать мангу: быстро найти тайтл, понять, о чём он, продолжить с того места, где остановился, и держать весь прогресс в одной библиотеке.

**Аудитория.** Зрители и читатели аниме и манги, которым нужен один удобный каталог и личный список вместо отдельных сайтов, закладок и заметок.

## Источник данных

Каталог строится на открытом **Kitsu API** (формат JSON:API). Он отдаёт аниме и мангу в одном формате: названия, постеры в нескольких размерах, категории, рейтинги, статус выхода, число серий и глав, а также поиск, фильтры, сортировку и постраничную выдачу. Для работы не нужны ключи и регистрация, поэтому приложение запускается сразу после установки.

**Что делает сетевой слой**

| Возможность | Как работает |
|---|---|
| Таймаут и пауза между запросами | Приложение не перегружает сервис и не зависает на медленной сети |
| Повтор при HTTP 429 | Один повторный запрос после паузы, затем понятная ошибка |
| Кэш в памяти | Одинаковые запросы в рамках сессии не повторяются |
| Кэш на диске (offline-first) | Последние успешные ответы сохраняются в Hive; без сети или при ошибке сервера показываются они, с пометкой «данные из кэша» |
| Типизированные ошибки | Сеть, лимит запросов, сервер и неверный формат ответа показываются разными понятными сообщениями с кнопкой «Повторить» |
| Устойчивость к данным | Запись с неполными данными пропускается и не ломает весь список |

**Как данные попадают в интерфейс.** DTO переводят ответ API в доменные модели (`MediaItem`), а экраны работают только с интерфейсом `MediaRepository`. Поиск, рекомендации по любимым жанрам и «Похожее» используют категории тайтлов из API.

**Запасной источник.** Рядом с Kitsu реализован второй источник, **Jikan (MyAnimeList)**: свой клиент, DTO и репозиторий, покрытые тестами. Смена источника сводится к одной строке в `core/di/providers.dart`, экраны при этом не меняются.

**Особенности данных.** Описания тайтлов приходят на английском; один запрос возвращает до 20 элементов, поэтому в каталоге сочетаются несколько запросов и кэш.

## Архитектура

Проект построен по принципам Clean Architecture: код разделён на слои, и каждый слой знает только о тех, что глубже.

| Слой | Ответственность |
|---|---|
| **`core/`** | Общее для всего приложения: DI, тема, константы, локализация, утилиты. В `di/providers.dart` выбираются реализации зависимостей: по умолчанию версии в памяти, а в `main.dart` через `overrides` подставляются хранилища на диске |
| **`domain/`** | Модели (`MediaItem`, `LibraryEntry` и др.), контракты репозиториев и типизированные ошибки (`NetworkException`, `RateLimitException`, `ServerException`, `ParseException`). Не зависит ни от Flutter, ни от сети, ни от базы данных |
| **`data/`** | Работа с внешним миром: API, DTO, локальные хранилища, демо-данные и реализации репозиториев |
| **`presentation/`** | Экраны, провайдеры состояния и переиспользуемые виджеты |

### Слой данных

| Модуль | Описание |
|---|---|
| **`api/`** | HTTP-клиент с таймаутом, паузой между запросами, повтором при HTTP 429, кэшем в памяти и offline-first кэшем на диске |
| **`dto/`** | Перевод JSON из API в доменные модели |
| **`local/`** | Хранилища на Hive и работа с фото профиля |
| **`mock/`** | Демо-данные для первого запуска и тестов |
| **`repositories/`** | Реализации контрактов для API, демо-данных и памяти |

### Принципы

- Экраны работают с интерфейсами репозиториев и не знают, откуда приходят данные
- Реализация каждой зависимости выбирается в одном месте
- Состояние обновляется сразу, хранилище догоняет следом
- Ошибки разных типов показываются пользователю разным понятным текстом

## Структура папок

```
lib/
├── core/                    # Ядро: DI, тема, константы, локализация, утилиты
│   ├── constants/

│   ├── errors/
│   └── repositories/
├── data/                    # Сеть, диск и реализации репозиториев
│   ├── api/
│   ├── dto/
│   ├── local/
│   ├── mock/
│   └── repositories/
├── presentation/            # Интерфейс
│   ├── pages/               # Экраны, сгруппированные по разделам
│   ├── providers/           # Состояние на Riverpod
│   └── widgets/             # Общие виджеты

└── main.dart                # Точка входа, открытие хранилищ, подстановка зависимостей
```

## Запуск

1. Установить зависимости:
```bash
   flutter pub get
```
2. Для iOS добавить ключ `NSPhotoLibraryUsageDescription` в `ios/Runner/Info.plist` — без него не работает выбор фото из галереи
3. Запустить приложение:
```bash
   flutter run
```
4. Прогнать тесты:
```bash
   flutter test
```
